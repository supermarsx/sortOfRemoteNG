## What this matrix covers

This page covers the integration registry, not the direct protocol clients in the [protocol matrix]({{ '/protocols/' | relative_url }}). Every registered panel uses persisted non-secret instance settings plus OS-vault references where applicable, and session-owned lifecycle handling reports the provider's real connect, disconnect, reconnect, and cleanup result. A saved session does not persist plaintext credentials or opaque live backend handles.

The verification column names deterministic repository checks, principally focused frontend tests and Rust loopback/fixture contract tests. They validate request shapes, error mapping, timeouts, persistence, and lifecycle behavior; they are not proof that a particular vendor deployment is reachable. No live vendor, appliance, mail-stack, or KDBX environment is part of this automated matrix.

## Regression contract

`tests/integrations/integrationSupportMatrix.test.ts` imports the authoritative top-level and Mail registries and requires one marker for every registered key in this page. Adding or removing a descriptor/sub-tab therefore makes the documentation check fail until this matrix is reconciled. The test currently asserts **26 top-level integration descriptors** and **9 Mail sub-tabs**.

For implementation details and risk boundaries, consult the source named by the focused tests and the [security overview]({{ '/security-overview/' | relative_url }}). For direct remote-session support, return to [Protocols]({{ '/protocols/' | relative_url }}).
